# Data layer (`lib/crm/data` + `lib/crm/presentation`)

## Canonical model (`data/model.ts`)

Source-agnostic entities with multi-connector provenance: every merged record
carries `sources: SourceRef[]` (connector + native id + sync time). The
product story is "merge several CRM systems"; `data/connectors.ts` lists them
with a merge `priority`. Per-connector field adapters don't exist yet — the
mock is born merged.

- `Account` — company; `isCustomer` drives new-vs-existing.
- `Opportunity` — deal; `businessUnitId` references the BU registry (slug,
  e.g. `"wyma"`, `"betcher"`); `marginPct` is stored, not derived (matches the
  wireframe where % ≠ margin/quoted).
- `LeadRecord` — **row-level leads are the source of all lead-side views**
  (KPIs, leads-by-source, source details, new-vs-existing). ~1600 rows.
- `ChannelPerformance` is a *derived* aggregate
  (`presentation/selectors.ts#aggregateChannels`), not stored. Per-channel
  cost lives in `ChannelMeta`.
- `FunnelRollups`/`LeadRollups` — corporate-wide pre-aggregates ("warehouse
  feeds"); intentionally NOT derivable from the sampled rows.

## Mock data generation (`data/mock-data.ts`)

- **Deterministic, no `Math.random()`** — stable for SSR + tests. Leads are
  generated by index arithmetic: channel mix via a weighted repeating pattern
  (Bulk 34 / Web 26 / RefWithin 18 / RefAcross 13 / After 9 per 100 — this is
  what makes Leads-by-Source read 34/26/18/13/9%), stage mix per 20
  (6 lead / 8 mql / 4 sql / 2 opp).
- Opportunities: 10 seeds × (1 open + 1 Closed Won), plus 4 seeds also get a
  `Closed Lost` "(alt bid)" variant so win rate (≈71.4%) is meaningful. If you
  add/remove lost deals, `access/auth.test.ts` hardcodes the Betcher count
  (currently 12).

## Per-year datasets (`data/datasets.ts`)

`databaseForYear("2024"|"2025"|"2026")` derives a year's `CrmDatabase` from
the base: values × factor (0.82 / 1 / 1.18), lead volume by slicing a stable
prefix (`factor / MAX_FACTOR` — proportions hold because the generation
patterns repeat), dates rebased preserving create→close span. Win rate / AOP /
new-customer % per year live in `YEAR_META`.

## Selectors & queries (`presentation/`)

- Selectors are pure: `(db) => view shape`. The facades
  `getLeadDashboard(db, session)` / `getFunnelDashboard(db, session)` apply
  financial gating (drop Cost / Margin columns) and return everything a tab
  renders. **Never re-introduce module-level precomputed view constants** —
  they freeze the data and broke filtering once already.
- `selectDeals(db, "open" | "booked")` = top 10 by quoted value; open excludes
  both terminal stages, booked = Closed Won only.

## Recipes

- **New filterable lead dimension**: add the field to `LeadRecord` +
  generation, extend `LeadFilter`/`filterLeads`/`leadFilterOptions`
  (`access/filters.ts`), add a `HeaderFilter` entry in
  `lead-management-dashboard.tsx`. Mirror for deals.
- **New mock year**: extend `availableYears` + `YEAR_META`; bump `MAX_FACTOR`
  if the new factor exceeds 1.18 (lead slicing depends on it). The SQL seed
  picks new years up automatically.
